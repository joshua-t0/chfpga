Overview
========

`xxvglink_array` bundles multiple **25G** bidirectional serial links using **GTY** transceivers on UltraScale+. Each lane carries a **64-bit AXI-Stream** packetized payload with SOF/EOF/CRC32 framing, identical to that of 10G Ethernet (IEEE 802.3ae). A single `xxvglink_core` instance manages the GTY quad QPLL and lane gearboxes; per-lane `xxvglink_tx` and `xxvglink_rx` modules handle framing. A bypass mode is available to loop TX data directly back to the RX output without going through the transceivers. **BSB** command/reply streams provide software-visible monitoring and diagnostics for each lane.

Parameters
==========

- **LANE_TO_LINK_MAP:** Maps each logical lane index to a physical GTY link number. The length of this array sets ``NUMBER_OF_LANES``.

- **LINK_TO_QUAD_MAP:** Maps each physical GTY link to a quad index (0 … N−1). The length of this array sets ``NUMBER_OF_LINKS``.

- **QUAD_TO_REFCLK_MAP:** Maps each quad to a reference clock index (0 … ``NUMBER_OF_REFCLK``−1).

- **IMPLEMENT_RX:** When ``TRUE`` (default), the receive path (GTY RX and `xxvglink_rx` instances) is instantiated. Set to ``FALSE`` for TX-only designs to reduce resource usage.

- **LANE_GROUP_MAP:** Maps each lane to a bypass group index. All lanes in the same group are bypassed together when the corresponding ``bypass`` control bit is set.

- **SIM:** When ``TRUE``, enables simulation-friendly GTY elaboration.

- **NUMBER_OF_LANES / NUMBER_OF_LINKS / NUMBER_OF_LANE_GROUPS / NUMBER_OF_REFCLK:** Derived from the map generics above. Do not override.

Interface
=========

SerDes
------

- ``tx_p`` / ``tx_n``: Differential serial output, one pair per GTY link.

- ``rx_p`` / ``rx_n``: Differential serial input, one pair per GTY link.

- ``refclk_p`` / ``refclk_n``: **156.25 MHz** differential reference clocks, one pair per reference clock index.

TX user interface (``axis_clk``)
---------------------------------

- ``s_axis_tx_tdata``: Array of 64-bit transmit data words, one per logical lane. The first byte transmitted is in the MSB (big-endian).

- ``s_axis_tx_tvalid``: Per-lane transmit data valid. The interface is non-blocking; data is accepted directly into a FIFO.

- ``s_axis_tx_tlast``: Per-lane end-of-packet indicator.

RX user interface (``axis_clk``)
----------------------------------

- ``m_axis_rx_tdata``: Array of 64-bit received data words, one per logical lane.

- ``m_axis_rx_tvalid``: Per-lane receive data valid (non-blocking).

- ``m_axis_rx_tlast``: Per-lane end-of-packet indicator.

- ``m_axis_rx_terror``: Active high on the cycle when ``tlast`` is asserted if an error (bad CRC or framing error) was detected in the frame.

Clocks and resets
-----------------

- ``axis_clk``: User clock for both the TX and RX AXIS interfaces. Must be fast enough so the average data rate over 512 words does not exceed 25 Gbps (~390 MWords/s).

- ``clk_out``: Word clock generated by the GTY transceivers, typically ~402.8 MHz (25 Gbps × 66/64 ÷ 64 bits/word). Connect to ``axis_clk`` for single-clock-domain operation.

- ``areset``: Asynchronous active-high reset.

Clock monitors
--------------

- ``refclk_div2``: Per-reference-clock toggle at half the 156.25 MHz reference frequency, for clock monitoring.

- ``txclk_div2``: Toggle at half the TX word clock frequency (``clk_out``), for clock monitoring.

Status
------

- ``resetdone``: Active high when the GTY transceivers have completed reset and are operational. Synchronous to ``axis_clk``.

BSB
---

- ``s_axis_bsb_t*`` / ``m_axis_bsb_t*`` on ``bsb_clk`` / ``bsb_rst``: Byte-serial command/reply interface for software register access to the monitoring and control registers.

Implementation details
======================

Architecture
------------

`xxvglink_array` instantiates one `xxvglink_core` (shared GTY quad/QPLL fabric) and, for each logical lane, one `xxvglink_tx` (packetizer) and one `xxvglink_rx` (depacketizer). Lanes whose ``LANE_TO_LINK_MAP`` entry is −1 are implemented as internal bypass lanes using `xxvglink_bypass`, which simulates the 64/66 gearbox throttling without using GTY resources.

Principle of operations
-----------------------

Each TX lane accepts a **non-blocking 64-bit AXI-Stream** on ``axis_clk``. Data is written into an asynchronous FIFO inside `xxvglink_tx` and read out on the GTY TX word clock. The TX framing state machine prepends a SOF control block, streams the payload, appends a CRC32 word and an EOF control block, and inserts IDLE control blocks whenever the FIFO is empty.

Each RX lane depacketizes the incoming 64-bit words from `xxvglink_core` on the recovered GTY RX clock, checks the CRC32, and writes the payload into an asynchronous FIFO that is read on ``axis_clk``. ``m_axis_rx_terror`` is asserted with ``tlast`` if the CRC check fails.

A per-lane-group bypass mux (controlled via the BSB ``bypass`` register bits) routes the TX AXIS input directly to the RX AXIS output, replacing the GTY data path. This is useful for loopback testing without physical links.

The BSB interface multiplexes per-lane monitoring counters (frame count, word count, error count, clock frequency, inter-frame delay) and a raw data-capture register for low-level debugging. Lane selection and monitoring type are configured via BSB control bytes.
