Parameters
==========

- **PLATFORM_TYPE:** FPGA platform type enumerated in the chFPGA package. Must be an Ultrascale+ variant; selects FIFO36E2 and URAM primitives appropriate for that device.
- **NUMBER_OF_INPUT_LANES:** Number of F-Engine channelizer input lanes. Determines the width of ``s_axis_tdata``. Defaults to 8.
- **BINS_PER_INPUT_WORD:** Number of frequency bins packed per 32-bit input word. Defaults to 4.
- **INPUT_WORD_WIDTH:** Bit width of each input lane data word (typically ``BINS_PER_INPUT_WORD × BITS_PER_BIN``).
- **CT_LEVEL:** Corner-turn level. ``1`` = local (no GTY links). ``2`` = local plus 4×4 intra-crate GTY links. ``3`` = Level 2 plus inter-crate QSFP GTY links.
- **LANE_TO_LINK_MAP:** Integer array mapping each logical lane index to a physical GTY link number.
- **LINK_TO_QUAD_MAP:** Integer array mapping each GTY link to its QUAD index.
- **QUAD_TO_REFCLK_MAP:** Integer array mapping each QUAD to its reference clock index.
- **LANE_TO_GROUP_MAP:** Integer array assigning each logical lane to a group. Backplane lanes are group 0; QSFP lanes are group 1.
- **OUTPUT_WIDTH:** Bit width of the aggregated AXI-Streaming output word (all output lanes concatenated).
- **NUMBER_OF_LINKS:** Total number of physical GTY serial links (transmit + receive).
- **NUMBER_OF_REFCLK:** Number of differential GTY reference clocks provided.
- **PRE_DECIMATE:** When ``TRUE``, enables a pre-decimation stage that halves the number of active frequency bins before corner-turning.

Interface
=========

Channelizer data input
-----------------------

- ``s_axis_tdata``: Per-lane channelizer data. All lanes share a common valid and last.
- ``s_axis_tvalid``: Shared valid flag for all input lanes. Non-blocking.
- ``s_axis_tlast``: Shared end-of-frame flag.

Corner-turn output
------------------

- ``m_axis_tvalid``: Output valid flag.
- ``m_axis_tdata``: Aggregated corner-turn output, ``OUTPUT_WIDTH`` bits wide.
- ``m_axis_tlast``: Output end-of-frame flag.

GTY serial links
----------------

- ``tx_p/tx_n``: Differential serial transmit, one pair per link.
- ``rx_p/rx_n``: Differential serial receive, one pair per link.
- ``refclk_p/refclk_n``: Differential 156.25 MHz reference clocks for GTY PLLs.
- ``refclk_div2``: Divided-by-two reference clock outputs for monitoring.
- ``txclk_div2``: Divided-by-two TX word clock.
- ``txclk_out``: TX word clock generated by the GTY PLL. Must be connected to ``axis_clk`` when GTY links are active.

Control and clocking
--------------------

- ``axis_clk``: AXI-Streaming data clock. Should be driven from ``txclk_out`` when GTY links are in use.
- ``rst``: Synchronous active-high reset (data-clock domain).
- ``arst``: Asynchronous reset for GTY transceiver reset sequences.
- ``resetdone``: Asserted when all GTY transceivers have completed their reset and lock sequences.
- ``s_axis_bsb_*/m_axis_bsb_*``: BSB command and reply byte streams for software-controlled register access.
- ``bsb_clk/bsb_rst``: Dedicated clock and synchronous reset for the BSB interface.

Sub-modules
-----------

The UCT Engine uses the following modules:

- :doc:`align64`: 64-bit multi-lane frame alignment module for aligning data streams from multiple sources
- :doc:`align64_fifo`: 64-bit alignment FIFO used by the align64 module

Implementation details
======================

Principle of operations
-----------------------

The UCT Engine performs up to three stages of corner-turning for Ultrascale+ FPGA platforms. At Level 1 a hardwired crossbar reorganises the 8 channelizer input lanes (each carrying ``BINS_PER_INPUT_WORD`` frequency bins) into ``BINS_PER_INPUT_WORD`` output lanes each containing data from all input channels for one bin, with no backplane communication. At Level 2 the output of the Level-1 crossbar is routed through 25-Gbps GTY serial links (``xxvglink_array``) to exchange data with up to 3 neighbouring boards on the same sub-backplane; the received streams are realigned by an :entity:`align64` instance and an optional pre-decimation stage culls the lowest 256 bins to fit within the link bandwidth. Level 3 repeats the process with a second set of GTY links and another :entity:`align64` to exchange data between sub-backplanes, enabling corner-turns across up to 16 boards.

Architecture
------------

The Level-1 crossbar is a hardwired process that repacks the input word array in a single registered clock cycle; it does not consume BRAM or DSP resources. For Levels 2 and 3, the architecture contains a ``xxvglink_array`` that multiplexes one bypass lane and up to three GTY links per corner-turn stage, a pre-shuffle lane remap and optional bin-decimation stage, an :entity:`align64` packet aligner with monitoring, and a post-shuffle lane remap stage to reorder channels into output-word order. A :entity:`bsb_router` with four ports (CT1, CT2, CT3, backplane shuffle) distributes the BSB byte-stream control interface to the appropriate register file; each level has its own ``bsb_regs`` block holding lane-map, monitoring-control, and status registers.

Clocking
--------

The data path runs on ``axis_clk``, which must be connected to ``txclk_out`` (the 402.8 MHz clock generated by the GTY TX PLL) whenever GTY links are active. An asynchronous reset ``arst`` is used to start the GTY reset sequence; it is not synchronised to ``txclk_out`` because it halts the clock. The synchronous ``rst`` is registered through a short pipeline before qualifying any state registers in the corner-turn logic. The BSB control interface runs on a separate ``bsb_clk`` and is isolated from ``axis_clk`` through clock-crossing logic inside ``bsb_regs``.
