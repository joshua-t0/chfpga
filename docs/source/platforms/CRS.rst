Clocking hardware
*****************


A 50 MHz oven-stabilized voltage-controlled crystal oscillator (VCXO) is the central clock source of the system.


The VCXO feeds the two on-board PLLs:


- AD9574 Fixed-frequency PLL, which receives a divided-by-two (25 MHz) version of the oscillator to generate fixed system clocks and provides the basic system clocks needed to boot the board, namely the FPGA's
processing system.
- HMC7044 Programmable PLL, which can 1) phase-lock the VCXO to a reference clock if needed and 2) generate a number of frequencies for the FPGA.


The board can operate with the VCXO not locked to an external reference.  The free-running VCXO is sufficiently accurate and stable enough to operate the system.
This allows the system to power up without the programmable PLL being configured, and allows the board to operate without external reference clock for stand-alone applications where multi-board synchnisation is not required.

The HMC7044 PLL can be configured over an SPI port connected to the FPGA's PS.  When configured, the HMC7044 can optionally phase-lock the VCXO to one of 4 sources:

  - On-board SMA Reference clock (typically 10 MHz)
  - Backplane reference clock  (typically 10 MHz)
  - Ethernet clock (125 MHz) recovered by the PHY
  - Clock generated by the FPGA (typically some recovered clock)

Operating the ADCs require the following clocks:


- RF_CLK: ADC sampling clock to the ADC tiles
- PL_CLK: signal processing clock to the PL
- PL_SYSREF: Synchronization clock provided to the PL
- RF_SYSREF: Synchronization clock provided to the ADC tiles

The OSCOUT (50 MHz) and copy of the PLL SMA or backplan 10 MHz referencence clocks are also required to implement unambiguous multiboard synchronization.

Clock frequencies
*****************

RF_CLK
------

We originally targeted ADC sampling frequencies of 3000 MSPS, and increased this to 3200 MSPS to provide a guard band to ease the analog antialiasing filter design.
We want firmware that can operate at both frequencies. The PLL provides this sampling frequency to the ADC tiles directly, which is possible since the maximum output frequency of the PLL is 3.2 GHz. We don't use the in internal PLL in the ADC tiles to minimize additive (uncorrelated) phase noise and maximally take advantage of common-mode phase noise rejection in cross-correlation measurements. This also potentially simplifies multi-tile and multi-chip ADC synchronization.

SYSREF
------

The PLL also generates SYSREF, which must follows the following rules:

- It must be a submultiple of Fs/16
- It shall be between 0.4 and 10 MHz inclusively (see DS926 RfSoC DC and AC characteristics datasheet, table 137).
- We add the constraints that SYSREF should also be a submultiple of the 10 MHz reference clock in case we need to synchonie logic between these clock domains.

The PLL requires the divided to be an even number, but that is guaranteed if we look for a sumbmultiple of fs/16.

We look for a common submultiple frequency::

   fcommon_max = 3000/16/k1 =  3200/16/k2

By simplifying the fraction ``k1/k2``, we find the lowest integers ``k1`` and ``k2`` that will yield a common frequency, and that frequency will the the largest common frequency for both fs/16::

   k1/k2 = 15/16  => k1 = 15, k2=16
   fcommon_max = 3000/16/k1 = 3200/16/k2 = 12.5 MHz

We need to divide `fcommon_max` further with an integer to get below 10 MHz, but we also want this frequency to be a submultiple of 10 MHz. So::

   fsysref = fcommmon_max/k3 = 10 MHz/k4
   k3/k4 = 12.5/10  = 25/20 = 5/4, -> k3=5, k4=4
   fsysref = 12.5/k3 = 10/k4 = 2.5 MHz

The final divider factors ``k`` applie dby the PLL di divide the ADC sampling freqeny down to SYSREF are::

   fs=3000, k=3000/2.5 = 16*k1*k3 = 1200
   fs=3200, k=3200/2.5 = 16*k2*k4 = 1280

Both values of 'k' are even numbers, as required by the PLL.

PL_CLK
------

PL_CLK is simply fs/8, since we process 8 samples at a time, giving a signal processing clock of 375 or 400 MHz, which is manageable on a Ultrascale+.


SYSCLK
------

SYSCLK is used by the FPGA's MMCMs to generate internal clocks independent of the data acquisiiton and processing clocks. Those generated frequencies are used to decode IRIGB and run peripherals such as SPI, I2C, buck converter synchronization etc.

For the CRS, SYSCLK is set to 10 MHz, which is a frequency that is generated easily whether the PLL VCO is at 3000 or 3200 MHz.

SYSCLK is a PLL-generated clock that can be optionally be aligned to the external 10 MHz reference clock once the PLL Sync procedure has been performed, but SYSCLK is present whether or not such an  external reference clock is provided or not. SYSCLK can therefore also be used as a proxy for the external reference clock, or simulate one if none is provided.

Synchronization
***************

The CRS provides the signals to the FPGA allowing for both multi-tile and multi-board synchronization.

PLL Synchronization
-------------------

PLL synchronization consists in aligning the ADC sampling and processing clocks to the external 10 MHz reference clock in order to ensure that the first sample of every frame is taken at a deterministic (fixed) delay after the 10 MHz external reference clock edge.

When the PLL is locked to the external reference, the 50 MHz VCXO edge, which is provided to the FPGA by OSCOUT, is mostly aligned to the external reference clock edge.

The PLL_SYNC signal needs ot be synchronous with the VCXO, and must provide adequate setup and hold times to that clock. Once PLL_SYNC is set, that signal is captured on the next rising edge of the VCXO, and the rising edge of the PLL outputs dividers will be aligned to the following rising edge of the VCXO.

A PLL_SYNC event is initiated by software by setting a control line on a BSB register, which is first aligned to a rising edge of the 10 MHz reference clock using a CDC clock. That 10 MHz edge is captured on the *falling* edge of 50 MHz OSCOUT to ensure maximum setup and hold time between those two edges. This provides maximum resilience to small phase alignment betreen OSCOUT and the reference clock. The captured edge is further delayed by 3 additional *falling* edges of OSCOUT, and is then sent out to the PLL to be captured by the next *rising* edge of the VCXO. Here again, the edge switching ensures maximal setup and hold time in case of misalignment tof OSCOUT and VCXO. The SYNC signal is captured on the next rising edge of VCXO, and the divider outputs restart their waveforms on the following rising edge of VCXO.  At that point, the PLL outputs should be aligned to the 10 MHz external reference clock.

ADC Synchronization
-------------------

The ADC synchronization consists in adjusting the ADC sampling clock delays in order to ensure deterministic capture of the ADC data and to set the data latency through the ADC internal logic to a known value used by all ADCs on all boards.

Array synchronization
---------------------

Array (i.e multi-board)  synchronization is performed using the IRIG-B signal.

- Each board continuously decode the IRIG-B time and interpolates the intra-second time down to a resolution of 10 ns.
- The host computer sets a future SYNC trigger time by setting a target IRIG-B time on every board. That time should be close to the *falling* edge of a 10 MHz clock.
- Once the boards detect the target time, they start the SYNC process on the next *rising* edge of the reference clock. The edge reversal is used to allow maximum setup/hold time.
- ADC Data framing restarts a fixed number of reference clock and/or signal processing clocks after the SYNC process has been triggered, therby ensuring every ADC bof every board starts sampling at the same time.

This process is relatively simple if the IRIG-B signal is synchronous to the refernece clock (e.g. both are generated by the same GPS receiver unit). In that case, the IRIG-B trigger is simply set a fixed offset from the current time, making sur eto round off and offset the subseconds to align the trigger to the falling edge of the reference clock. An additional delay tweak of multiples of the reference clock can be introduced to ensure that the ADC frame will end up being aligned with the IRIG-B second.

If the reference clock is not synchronous to the IRIG-B signal (e.g. reference clock is provided by a hydrogen MASER, and IRIG-B is form a GPS receiver), the software will need to track the drift between the IRIG-B and the reference clock, and anticipate the extra offset needed to set a  IRIG-B trigger that will be close to the falling edge of the reference clock. This requires the drift between the two signal to be slow enough and predictible enough to allow relative timing of the trigger within +/-50 ns.
