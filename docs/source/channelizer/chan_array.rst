Overview
========

The `chan_array` entity contains the ADC data acquisition blocks and channelizer array extracted from `chfpga` for improved modularity. This module encapsulates:

- ADC generation logic (EV8AQ160 and AXIS types)
- Channel router for BSB command routing
- Channelizer array instantiation

**Note**: The following remain in `chfpga` for top-level coordination reasons:

- Channelizer clock generation (``chan_clk_gen``) — stays in `chfpga` for top-level clock coordination.

The channel output alignment logic (``chan_align_blk``) is implemented inside `chan_array`. See `Channelizer output alignment`_ below.

Parameters
==========

- **PLATFORM_TYPE:** Target FPGA platform. Selects platform-specific primitives. Defined as an enumerated type in :doc:`../chfpga_package`.
- **ADC_TYPE:** Type of ADC interface. Selects between EV8AQ160 (differential SERDES-based) and AXIS (AXI-Streaming) ADC front-ends.
- **NUMBER_OF_ADCS:** Total number of ADC channels to instantiate.
- **NUMBER_OF_CHANNELIZERS:** Number of channelizer instances. Defaults to ``NUMBER_OF_ADCS``.
- **NUMBER_OF_CHANNELIZERS_WITH_FFT:** Number of channelizers that include an FFT. Defaults to ``NUMBER_OF_CHANNELIZERS``.
- **FFT_TYPE:** Selects the FFT configuration (e.g., ``CHIME``, ``D3A``, ``HIRAX``). Propagated to each ``chan`` instance.
- **CAPTURE_TYPE:** Selects the capture engine type (``BRAM`` or ``URAM``). Determines which capture interface is active.
- **ADC_IS_DIFFERENTIAL:** Per-ADC, per-line differential/single-ended selection array. Indices 0–7 are the data lines; index 8 is the clock line.
- **ADC_PROVIDE_BUFFERED_DIVCLK:** Per-ADC flag; when ``TRUE``, that ADCDAQ exports a BUFG-buffered word clock.
- **ADC_INSTANTIATE_PLL:** Per-ADC flag; when ``TRUE``, that ADCDAQ instantiates a PLL to generate globally-buffered IOCLK and DIVCLK for export to other ADCDAQ instances.
- **ADC_USE_EXT_DATA_CLK:** Per-ADC flag; when ``TRUE``, the ADCDAQ uses externally provided IOCLK/DIVCLK rather than locally generated clocks.
- **ADC_CLOCKING_REGION_MAP:** Per-ADC clock region mapping for BUFR/BUFIO placement. Entries map each data/clock line to a clock region integer.
- **CHAN_CLK_SOURCE_LANE:** Index of the ADC lane whose clock drives the channelizer clock network.
- **ADC_TO_ADC_BOARD_MAP:** Maps each ADC index to its FMC board index, used to select the correct reference clock for ADCDAQ delay calibration.
- **NUMBER_OF_ADC_BOARDS:** Number of FMC ADC mezzanine boards.
- **CT_CLK_SOURCE:** Source for the corner-turn clock (e.g., ``CORR_CLK``).
- **CHAN_CLK_SOURCE:** Source for the channelizer processing clocks. ``ADC`` uses the ADC clock directly; ``MMCM`` uses multi-phase MMCM-derived clocks.
- **CORR_TYPE:** Correlator type, used to configure the corner-turn interface.
- **CT_TYPE:** Corner-turn type, determines the width of the output data bus.
- **SIM:** Simulation mode flag. When ``TRUE``, simulation-friendly behavior is enabled.

Interface
=========

ADC physical interface (EV8AQ160)
----------------------------------

- ``adc_data_p/n``: Differential 8-bit data buses from each EV8AQ160 ADC.
- ``adc_clk_p/n``: Differential data clocks from each ADC.

ADC AXIS interface
------------------

- ``adc_axis_tdata/tvalid/adc_axis_clk``: AXI-Streaming data and clock inputs for AXIS-type ADC front-ends.
- ``adc_or/adc_ov``: Per-ADC overrange and overvoltage flags.
- ``adc_clkout``: Divided ADC sampling clock from the tile (for monitoring only).
- ``adc_sysref``: PL SYSREF signal reclocked through the ADC axis clock.

ADCDAQ control
--------------

- ``adcdaq_reset``: Asynchronous reset for all ADCDAQ instances. Asserted during ADC SYNC sequencing.
- ``adc_clk``: Word clock output from one ADC, forwarded to the clocks module.
- ``adc_clk_div2``: Per-ADC logic signal pulsing at half the word clock rate, for frequency monitoring.

Reference and utility clocks
-----------------------------

- ``fmc_refclk``: Per-board reference clocks used for ADC clock delay calibration inside ADCDAQ.
- ``clk200``: Stable 200 MHz clock for IDELAYCTRL initialization.

Channelizer clocks
------------------

- ``chan_clk/chan_reset``: Array of channelizer processing clocks and synchronous resets, generated by the top-level ``chan_clk_gen`` module.
- ``ct_clk/ct_reset``: Corner-turn clock and synchronous reset, used for output alignment and the output data bus.

Channelizer output
------------------

- ``chan_out_tdata/tuser/tvalid/tlast``: Non-blocking AXI4-Streaming output buses from each channelizer, synchronous to ``ct_clk``.
- ``adc_tvalid/adc_tlast``: Per-ADC valid and last flags, exported for system-level event counting.

Data capture
------------

- ``m_axis_prober_tdata/tvalid/tlast/tready``: 8-bit blocking AXI-Streaming PROBER or UCAP capture outputs (one port per active capture channel).
- ``axis_cap_clk``: Clock for the capture output interface.

BSB control interfaces
----------------------

- ``s_axis_bsb_*/m_axis_bsb_*``: BSB command/reply interface routing commands to the channelizer array and ADCDAQ instances.
- ``bsb_clk/bsb_rst``: BSB clock and synchronous reset.
- ``s_axis_ucap_bsb_*/m_axis_ucap_bsb_*``: Separate BSB interface for the UCAP capture module, connected directly to the top-level router.

Description
===========

The `chan_array` module provides a modular interface for ADC data acquisition and channelization. It receives clock and reset signals generated by the top-level `chfpga` module and outputs channelized data along with control and monitoring interfaces.

Key Features
------------

- Supports multiple ADC types (EV8AQ160 and AXIS)
- Routes BSB commands to individual channelizers and ADCDAQ blocks
- Provides channelized output data streams
- Exposes capture interfaces for data monitoring (PROBER and UCAP)
- Generates ADC clock signals for the clocks module

Channelizer output alignment
----------------------------

.. note::
   ``chan_align_blk`` runs on the corner-turn clock (``ct_clk``), which is also a port of ``chan_array``. The block is implemented inside ``chan_array``; ``chan_out_almost_empty`` and ``chan_out_send`` are internal signals and no longer appear on the entity interface.

All channelizer output FIFOs must be read simultaneously so that the corner-turn engine always receives one word from every antenna at the same time. The ``chan_align_blk`` enforces this by gating the global ``send`` signal: data is only forwarded when every channelizer output FIFO has at least one word available.

The mechanism uses a two-stage pipeline to absorb the round-trip propagation delay between the FIFOs and the central arbiter:

1. The ``almost_empty`` flags from each channelizer output FIFO are registered twice (``almost_empty_reg1``, ``almost_empty_reg2``) to allow the signals to propagate from their source flops to a central point.
2. The registered flags are OR-reduced: ``send = NOT OR(almost_empty_reg2)``. The ``send`` signal is ``'0'`` (pause) if any lane is almost empty, ``'1'`` (transmit) otherwise.
3. ``send`` is registered twice again (``send_reg1``, ``send_reg2``) before being broadcast back to ``chan_out_send`` on each channelizer.

The two-stage pipeline on each direction means the FIFO almost-empty threshold must be set at least four words above zero (two cycles of propagation each way) so that the FIFOs cannot underrun during the time it takes the ``send`` signal to propagate back after ``almost_empty`` is asserted.

The ``send_reg1/2`` and ``almost_empty_reg1/2`` signals are tagged ``keep`` to prevent the synthesis tool from collapsing them into a shift register, preserving the intended pipelining and placement flexibility.


Implementation details
======================

Principle of operations
-----------------------

`chan_array` aggregates all ADC front-end blocks (`ADCDAQ` or AXIS-type) and their associated channelizer pipeline stages into a single entity, decoupling the top-level `chfpga` module from platform-specific ADC details. Each ADC channel feeds a dedicated `chan` instance that includes a function generator (`FUNCGEN`), FFT, scaler, and capture block (`PROBER` or `UCAP`). A BSB channel router distributes control commands to each instance. The ``chan_align_blk`` enforces simultaneous readout of all channelizer output FIFOs so the corner-turn engine always receives one word per antenna per clock.

Clocking
--------

Channelizer processing clocks (``chan_clk``) and their synchronous resets are generated by the top-level ``chan_clk_gen`` module and passed in as ports. The corner-turn clock (``ct_clk``) is also an input and is used for the output alignment logic and the channelizer output data bus. The ADC capture word clock (``adc_clk``) is exported back to the top level for clock monitoring.
