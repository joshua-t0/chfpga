Entity documentation

.. autoentity:: xglink_descrambler

Parameters
==========

- **RX_DATA_WIDTH:** Width of the data bus in bits. Default is 16. Must match the width used by the companion `xglink_scrambler` on the transmit side.

Interface
=========

Data
----

- ``SCRAMBLED_DATA_IN``: Scrambled input data (``RX_DATA_WIDTH`` bits). Bit 0 is the first bit that arrived from the serial link.

- ``UNSCRAMBLED_DATA_OUT``: Descrambled output (``RX_DATA_WIDTH`` bits). Registered; valid one clock after ``DATA_VALID_IN`` is asserted.

Control
-------

- ``DATA_VALID_IN``: Data-valid enable. The LFSR state and the output register are only updated when this signal is ``'1'``.

Clock and reset
---------------

- ``USER_CLK``: Synchronous clock.

- ``SYSTEM_RESET``: Synchronous reset. Initialises the 58-bit LFSR to the all-alternating seed ``"0101…01"``.

Implementation details
======================

Principle of operations
-----------------------

The descrambler implements the self-synchronising LFSR defined by the 64B/66B standard (polynomial :math:`1 + x^{39} + x^{58}`). For each incoming bit *i*, the descrambled bit is:

.. math::

   d_i = s_i \oplus \text{LFSR}[38] \oplus \text{LFSR}[57]

where ``LFSR`` is then shifted left and loaded with the *scrambled* bit :math:`s_i`. Because the LFSR is driven by received data rather than by the output, synchronisation is acquired automatically within 58 received bits after reset or a link restart — no explicit handshake is required.

The 58-bit shift register is evaluated combinatorially for all ``RX_DATA_WIDTH`` bits in a single process, and the result is registered on the rising edge of ``USER_CLK`` when ``DATA_VALID_IN='1'``. The module is generated by the Xilinx 7-Series FPGAs Transceivers Wizard and is instantiated in `xglink_rx`.
