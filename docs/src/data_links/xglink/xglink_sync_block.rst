Entity documentation
--------------------

.. autoentity:: xglink_sync_block

Parameters
==========

- **INITIALISE:** 6-bit initialisation vector for the six flip-flops in the synchroniser chain. Each bit sets the power-on value of the corresponding flop. Default is ``"000000"`` (all zeroes).

Interface
=========

Data
----

- ``data_in``: Single-bit asynchronous input signal to be synchronised. May originate from any clock domain.

- ``data_out``: Single-bit synchronised output, valid in the ``clk`` domain after the synchroniser latency.

Clock
-----

- ``clk``: Destination clock domain. All six flip-flops are clocked by this signal.

Implementation details
======================

Principle of operations
-----------------------

The module implements a six-stage flip-flop synchroniser chain (``data_sync_reg1`` through ``data_sync_reg6``) instantiated as individual ``FD`` primitives. All six stages carry the ``ASYNC_REG`` attribute (set to ``"true"``) so the placer and router keep them physically close, minimising routing delay between them and reducing the mean-time-between-failure for metastability.

The ``shreg_extract`` attribute is set to ``"no"`` on every stage to prevent the synthesis tool from collapsing the chain into an SRL shift register, which would not provide metastability protection.

The six-stage depth provides substantially lower metastability probability than the conventional two-stage synchroniser at the expense of six clock cycles of latency. This is acceptable for single-bit control and status signals.

The module is generated by the Xilinx 7-Series FPGAs Transceivers Wizard and is used throughout `xglink_rx_startup_fsm` and `xglink_tx_startup_fsm` to cross reset-done and lock signals between clock domains.
