.. autoentity:: xglink_tx_startup_fsm

Parameters
==========

- **STABLE_CLOCK_PERIOD:** Period of ``STABLE_CLOCK`` in nanoseconds (range 4–250). Default is 8 ns (125 MHz). All internal time-out counters are derived from this value so absolute durations are clock-frequency independent.

- **RETRY_COUNTER_BITWIDTH:** Width of the retry counter output (range 2–8). Default is 8 bits (up to 255 retries).

- **TX_QPLL_USED:** Set to ``True`` when the TX path uses the QPLL (10 Gb/s operation). When ``False``, the CPLL path is assumed.

- **RX_QPLL_USED:** Set to ``True`` when the RX startup FSM also uses the QPLL, so QPLL-reset coordination between TX and RX FSMs is correct.

- **PHASE_ALIGNMENT_MANUAL:** When ``True``, the FSM drives ``RUN_PHALIGNMENT`` and waits for ``PHALIGNMENT_DONE`` before completing startup. For single-lane designs the automatic alignment is sufficient and this can be set to ``False``.

Interface
=========

Clocks
------

- ``STABLE_CLOCK``: Stable free-running clock present from power-on. Drives all time-out counters.

- ``TXUSERCLK``: TX user clock from the GTX. Used to synchronise reset-done flags across the clock domain boundary.

Status inputs
-------------

- ``SOFT_RESET``: User-driven reset; can be asserted at any time to restart the TX initialization sequence.

- ``QPLLREFCLKLOST`` / ``CPLLREFCLKLOST``: Reference-clock loss indicators from the QPLL / CPLL.

- ``QPLLLOCK`` / ``CPLLLOCK``: PLL lock indicators from the QPLL / CPLL.

- ``TXRESETDONE``: GTX ``TXRESETDONE`` output, indicating the TX PMA and PCS are ready.

- ``MMCM_LOCK``: MMCM locked indicator.

- ``PHALIGNMENT_DONE``: Asserted by the phase-alignment logic when manual TX phase alignment has completed.

Control outputs
---------------

- ``GTTXRESET``: Hard GTX TX reset; driven high during the reset sequence.

- ``MMCM_RESET``: Resets the TX-path MMCM.

- ``QPLL_RESET``: Resets the QPLL (only when ``TX_QPLL_USED=True``).

- ``CPLL_RESET``: Resets the CPLL (only when ``TX_QPLL_USED=False``).

- ``TX_FSM_RESET_DONE``: Asserted when the complete TX initialization sequence has finished successfully.

- ``TXUSERRDY``: Driven high at the appropriate point in the sequence to enable the GTX TX data path.

- ``RUN_PHALIGNMENT``: Triggers the external phase-alignment logic when the GTX TX clock is stable.

- ``RESET_PHALIGNMENT``: Resets the phase-alignment logic at the start of each retry.

- ``RETRY_COUNTER``: Saturating counter that records how many times the FSM retried initialization before succeeding.

Implementation details
======================

Principle of operations
-----------------------

The FSM sequences through the following states: ``INIT → ASSERT_ALL_RESETS → WAIT_FOR_PLL_LOCK → RELEASE_PLL_RESET → WAIT_FOR_TXOUTCLK → RELEASE_MMCM_RESET → WAIT_FOR_TXUSRCLK → WAIT_RESET_DONE → DO_PHASE_ALIGNMENT → RESET_FSM_DONE``.

All time-out durations (500 ns post-config delay, 2 ms PLL lock wait, 500 µs MMCM lock wait, 1 µs margins, etc.) are derived from ``STABLE_CLOCK_PERIOD`` at elaboration time.

The PLL reference-clock loss and rising-edge lock signals are synchronised to ``STABLE_CLOCK`` via `xglink_sync_block` instances. If the QPLL (or CPLL) was already reset by the RX FSM in a shared configuration, the TX FSM skips a redundant reset using the ``TX_QPLL_USED`` / ``RX_QPLL_USED`` coordination.

On failure (time-out waiting for ``TXRESETDONE`` or ``MMCM_LOCK``), the FSM restarts from ``ASSERT_ALL_RESETS`` and increments ``RETRY_COUNTER``.

The module is generated by the Xilinx 7-Series FPGAs Transceivers Wizard and is instantiated in `xglink_core`.
