Entity documentation
====================

.. autoentity:: xxvglink_block_sync

Parameters
==========

- **SH_CNT_MAX:** Number of consecutive valid 64B/66B sync headers that must be observed before block lock is declared (default: 64).

- **SH_INVALID_CNT_MAX:** Number of invalid sync headers within a ``SH_CNT_MAX`` window that causes lock to be lost (default: 16).

Interface
=========

- ``rxheader_in``: 2-bit 64B/66B block header received from the GTY gearbox. Valid values are ``01`` (data block) or ``10`` (control/ordered-set block).

- ``rxheadervalid_in``: Asserted by the GTY gearbox when ``rxheader_in`` contains a valid header.

- ``blocksync_out``: Active high when block lock has been acquired. Remains high until too many consecutive invalid headers are observed.

- ``rxgearboxslip_out``: Single-cycle pulse output to the GTY ``RXGEARBOXSLIP`` port requesting a 1-bit slip to re-align the gearbox.

- ``clk``: Word clock (synchronous to the received data path).

- ``rst``: Synchronous active-high reset.

Implementation details
======================

Principle of operations
-----------------------

`xxvglink_block_sync` implements the IEEE 802.3 **64B/66B block synchronization** state machine originally generated by the Xilinx 7-Series Transceivers Wizard and adapted for GTY use. It monitors the 2-bit sync headers delivered by the GTY gearbox and drives ``RXGEARBOXSLIP`` until the header stream is properly aligned.

The FSM has six one-hot states: **begin** (start new observation window), **test_sh** (wait for a valid header strobe), **sh_valid** (valid header seen), **sh_invalid** (invalid header seen), **slip** (request a 1-bit gearbox slip and wait 32 cycles), and **sync_done** (lock transition). A header is considered valid when ``rxheader_in`` is ``01`` or ``10``; any other value is invalid. Lock (``blocksync_out``) is asserted after ``SH_CNT_MAX`` consecutive valid headers with zero invalid ones; it is dropped when ``SH_INVALID_CNT_MAX`` invalid headers are detected within a ``SH_CNT_MAX``-header window, causing a new slip and re-acquisition cycle.

Key Features
^^^^^^^^^^^^

- **Standard-compliant**: Implements the 64B/66B block-sync algorithm as specified by IEEE 802.3
- **Configurable thresholds**: ``SH_CNT_MAX`` and ``SH_INVALID_CNT_MAX`` control acquisition speed vs. noise tolerance
- **Slip arbitration**: Issues a single-cycle ``RXGEARBOXSLIP`` pulse and waits 32 cycles for the slip to propagate before re-testing

Usage in XXVGLINK
^^^^^^^^^^^^^^^^^

The block sync state machine is used in the :entity:`xxvglink_rx` module to establish and maintain synchronization with the incoming 64B/66B encoded data stream from the GTY transceiver.
