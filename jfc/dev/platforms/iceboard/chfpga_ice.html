chfpga_ice platform wrapper (hdl/platforms/ice/chfpga_ice.vhd)

Description

This platform wrapper is the top-level that is used to implement chFPGA on the IceBoard platform (part number MGK7MB). It is used with multiple firmware configurations.

The platform defines the I/Os that connect the FPGA with the IceBoard-specific hardware

Key hardware-specific parameters

The wrapper hard-codes the following parameters that are specific to the IceBoard platform:

Platform ID

PLATFORM_TYPE = MGK7MB

Clocking

System reference clock

The reference clock used to generate system clocks is the 125 MHz clock provided as the SFP reference clock (SYSTEM_CLOCK_SOURCE = SFP_REFCLK, SYSTEM_CLOCK_FREQ=125.0).

The module clocks takes this clock and uses a MMCM to generate the 125 MHz, 200 MHz, 250 MHz and 62.5 MHz system clocks.

Channelizer clocks

chfpga can operate the channelizer either on a single-phase clock or a multi-phase clock. In both case, the clock is provided from ADC0. If single clock is selected (CHAN_CLK_SOURCE=ADC), the buffered bersion of the clock is sent to all ADCs. If an multi-phase clock is selected (CHAN_CLK_SOURCE=MMCM), either the ADC clock or the 200 MHz system clock (generated by the MMCM above) can be used to generate 8 independenr channelizer clocks, each shifted in frequency by 45 degrees.

We use to operate the ice platform using multi-phase clock, with the expectation this will reduce the switching noise caused by the FPGA. But there is little evidence this actually helps. In the new configuration, we simply use a single clock (CHAN_CLK_SOURCE=ADC). This preserves clocking resources, but does not save us from having to use FIFOs (i.e. BRAMs) after the ADCDAQ (to ensure continuous data flow and cross between ADC and channelizer clock domains) and at the output of the channelizers (to ensure frame alignment and cross between channelizer and corner-turn clock domains).

In the case of multi-phase channlizer clocks, there used to be a timing constraints to select which clock source would be used for timing analysis. This line is commented out for single-phase channelizer clock.

Corner-turn clock

The corner-turn clock source CT_CLK_SOURCE depends on the mode of operation, and in selected in the configuration file through the CONFIG_CT_CLK_SOURCE parameter.

In ct (corner-turn) configs, the Corner-turn engine operate on the backplane transmitter clock (CT_CLK_SOURCE = BP_SHUFFLE_TXCLK) (about 244 MHz). The extra speed compared to the 200 MHz channelizer clock provides the extra clock cycles required to transmit the packet headers and flags.

In corr* (correlator) mode(s), a simple internal corner-turning is used (CT_LEVEL=1) and backplane transitters are not implemented, so that clock is not available. We therefore use the internal CORR_CLOCK, which is a 250 MHz clock generated from the system clock by the clocks module.

Note

We used to use the 1st stage of the full bct_engine corner-turn engine to feed the correlator, which added the headers and flags, and therefore required a higher clock speed. Hence the historical use of CORR_CLK. Modern compiles use the new simple corner-turn and new UCORR44, which does not expect any extra information. CRS platforms operate at higher speed (400 MHz) and avoids using an even faster clock by using the channelizer clock as a corner-turn engine clock (CT_CLK_SOURCE = ADC_CLK) and correlator clocks . The Ice platform could do this, and CORR_CLK could probably be completely removed from the design.

BSB interface

BSB bus is connected to the 1 Gb Ethernet UDP/MAC that interfaces the SFP port using a SGMII interface (serial interface implemented using the gigabit transceiver) (BSB_TYPE = UDP_SGMII). UDP packets received by the board over the SFP interface will be sent directly on the BSB bus, and replies will be sent back to the source as UDP packets as well. The communication is done directly with the FPGA (i.e. the ARM processor not involved).

Implementation details

Architecture

The entity instantiates chfpga with IceBoard-specific generics, and directly instantiates Xilinx primitives for clock input buffering:

  • IBUFDS_GTE2 for each of the differential MGT reference clock inputs (mgt_clk10, mgt_clk100, mgt_clk200, mgt_clk125), buffered through BUFG or BUFH.

  • A BUFR for the single-ended raw_clk10 input.

  • IOBUF primitives for all bidirectional signals (sma_a, sma_b_fpga_led2, fpga_led1_bp_sma, gpio_rst_n, gpio_irq_n, uart_tx, uart_rx, arm_irq_n, flash_spi_cs_n, bp_gpio_int).

  • IBUFGDS for the differential bp_time and bp_trig inputs.

Principle of operations

The 125 MHz SFP reference clock (sfp_clk_p/n) is the system reference inside chfpga, where an MMCM generates 62.5, 125, 200, and 250 MHz system clocks. ADC data arrives via 16 DDR parallel buses from the two MGADC08 FMC mezzanines (8 channels each). The ADC word clock from ADC 0 is BUFG-buffered by chfpga and used to clock all channelizers.

The BSB interface uses an SGMII 1G Ethernet link over the SFP port, driven by the GTX transceiver. This means the ARM processor communicates with the FPGA via standard UDP/IP packets over Ethernet, with no DMA or AXI interconnect involved.

For configurations with CT_LEVEL > 1, the backplane shuffle GTX links are enabled; their IO buffers are otherwise suppressed to avoid DRC errors on unconnected pins. The 10G Ethernet ports are only active when DATA_LINK_TYPE = XGE.
